Paste after Prompt 1 completes successfully. This is the core of the system.Build the WhatsApp Cloud API webhook and full conversation state machine.FILE: src/routes/whatsapp.js================================WEBHOOK SETUP:- GET /webhooks/whatsapp → verify token handshake with Meta- POST /webhooks/whatsapp → receive all incoming messagesMESSAGE HANDLER:Extract from payload: customerPhone, messageText, messageTypeLoad session from Supabase sessions table by phone.Route to the correct step handler based on session.step.──────────────────────────────────────────────────CONVERSATION FLOW STATE MACHINE──────────────────────────────────────────────────STEP: identify  - Check settings table: if vacation_mode = true →    send "We are on a short break. Back soon! 🌾" and stop.  - Query customers table by phone.  - If found → update session.step = "menu", greet by name,    send product menu (see MENU MESSAGE below).  - If not found → update session.step = "collect_name",    send: "Welcome to Wild Wild Yeast! 🌾 We bake with love.    First, what is your name?"STEP: collect_name  - Save name to session.temp.name  - Update step = "collect_address"  - Reply: "Nice to meet you, {name}! What is your delivery address?"STEP: collect_address  - Save to session.temp.address  - Update step = "collect_pincode"  - Reply: "And your pincode?"STEP: collect_pincode  - Save to session.temp.pincode  - INSERT into customers table (phone, name, address, pincode)  - Update step = "menu"  - Send welcome message + product menuMENU MESSAGE (send as WhatsApp list message or numbered text):  "Here is what we have for you today 🍞  Reply with a number to add to your order:  1. Classic Sourdough Loaf - ₹280  2. Multigrain Sourdough - ₹320  3. Ginger Ale (500ml) - ₹150  4. Kombucha (500ml) - ₹180  5. Water Kefir (500ml) - ₹160  ─────────────  Type 0 to Checkout"STEP: menu  - If message = "0" → go to CHECKOUT  - If message is 1-5 → save product selection to session.temp.selected_product    update step = "select_date"    Reply: "Great choice! What delivery date would you like?    Earliest available: {calculateDeliveryDate()}    Reply in format: DD/MM/YYYY"  - If message is unrecognised → route to SUPPORT (Claude AI)STEP: select_date  - Parse date from message (DD/MM/YYYY)  - Validate: must be >= calculateDeliveryDate()  - Ask: "How many would you like? (Reply with a number)"  - Update step = "select_quantity"STEP: select_quantity  - Parse quantity (integer, 1-20)  - Add to cart: { productId, productName, price, quantity, deliveryDate }  - Update session.cart  - Update step = "menu"  - Reply: "Added! ✅ Your cart has {n} item(s).    Continue ordering or type 0 to checkout."──────────────────────────────────────────────────STEP: checkout──────────────────────────────────────────────────  - Display full cart summary:    "Your order summary 🛒    ─────────────    {for each item: name x qty = ₹subtotal (delivery: date)}    ─────────────    Subtotal: ₹{subtotal}    Loyalty discount: {discountPercent}%    TOTAL: ₹{finalTotal}    ─────────────    To modify quantities, reply: CHANGE {item number} {new qty}    To confirm and pay, reply: CONFIRM"  - Update step = "confirm_order"STEP: confirm_order  - If message starts with "CHANGE":    parse item number and new quantity, update cart, recalculate,    re-display checkout summary  - If message = "CONFIRM":    → CREATE ORDER (see below)──────────────────────────────────────────────────CREATE ORDER FLOW──────────────────────────────────────────────────1. Generate order_number: WWY-{YYYY}-{4 digit random}2. Apply applyDiscounts() for final total3. Determine baker via findBestBaker(pincode, productIds)4. INSERT into orders table (status: pending, payment: pending)5. Create Razorpay order via API:   amount: finalTotal * 100 (paise), currency: INR,   notes: { order_id: uuid, order_number }6. Send payment link to customer:   "Your order {order_number} is confirmed! 🎉   Total payable: ₹{finalTotal}   Pay here: {razorpayPaymentLink}   This link expires in 15 minutes."7. Clear session cart, set step = "identify"──────────────────────────────────────────────────SUPPORT FALLBACK──────────────────────────────────────────────────Any unrecognised message at any step → send to Claude claude-haiku-4-5:System prompt:  "You are a warm, friendly customer support agent for Wild Wild Yeast (WWY),   an artisanal sourdough and fermented goods brand in India. You help   customers with product questions, delivery queries, ingredients, and   order status. Keep responses concise and conversational. Never make up   prices or delivery times — say you will check and follow up.   Always end with an offer to help them order."Pass last 5 messages as conversation history.Send Claude response back via WhatsApp.Prompt 3 — Payments, Invoicing & Owner Notification⚠  Paste after the WhatsApp engine is working.Build the Razorpay webhook, PDF invoice generator, and email notification.FILE: src/routes/payments.js================================POST /webhooks/razorpay- Verify Razorpay webhook signature using RAZORPAY_WEBHOOK_SECRET- On event "payment.captured":  1. Extract order_id from payment.entity.notes  2. UPDATE orders SET payment_status = 'paid' WHERE id = order_id  3. Fetch full order + customer details from Supabase  4. Call generatePDFInvoice(order) → returns local file path  5. Upload PDF to Supabase Storage bucket "invoices"  6. UPDATE orders SET invoice_url = publicUrl  7. Send WhatsApp message to customer:     "Payment received! ✅ Thank you {name}.     Order {order_number} is confirmed.     Download your invoice: {invoice_url}     We will update you on the day of delivery. 🌾"  8. Send email to OWNER_EMAIL (see EMAIL FORMAT below)  9. Assign baker via findBestBaker() if not already assignedFILE: src/services/invoice.js================================generatePDFInvoice(order):- Use pdfkit to create a professional PDF invoice- Header: Wild Wild Yeast logo text, tagline "Baked with Wild Fermentation"- Invoice Number: {order_number}- Date: order created_at formatted as DD MMM YYYY- Bill To: customer name, phone, address, pincode- Items table: Product | Qty | Unit Price | Total- Show loyalty discount line if applicable- Grand Total (bold)- Footer: "Thank you for supporting artisan baking."- Save to /tmp/invoice_{order_number}.pdf- Return file pathFILE: src/services/email.js================================sendOwnerNotification(order, customer):- Use nodemailer with Gmail App Password- To: OWNER_EMAIL- Subject: "New Order {order_number} - ₹{total_amount} - {customer.name}"- Body (HTML):  - Order number, date/time  - Customer: name, phone, address, pincode  - Items list with quantities and prices  - Delivery date(s)  - Total amount (highlight in green)  - Assigned baker name (if found)  - Link to Supabase Studio orders tablefindBestBaker(pincode, productIds):- Query bakers where pincodes @> ARRAY[pincode]- Filter: is_active = true- Filter: specialty_ids contains all productIds- Pick first available- UPDATE orders SET baker_id = baker.id- Return baker object or nullPrompt 4 — Baker Dashboard (White-Label)⚠  This creates a mobile-friendly, no-login dashboard for your baker partners.Create the baker partner dashboard as a single HTML file.FILE: public/baker-dashboard.html================================OVERVIEW:A mobile-first single-page HTML/CSS/JS dashboard.No login required — access via ?token=SHARE_TOKEN in URL.Uses Supabase JS client directly (with anon key, RLS enforced).LAYOUT:- Header: "WWY Baker Dashboard" + baker name + today's date- Section 1: "Today's Bake List" — aggregated product totals for today  e.g. "Classic Sourdough x 8 | Ginger Ale x 4"- Section 2: Individual orders list — each card shows:  - Customer name and area/pincode  - Delivery time slot (if available)  - Items ordered  - Status badge (placed / baking / ready / delivered)  - A button "Mark Ready" — updates delivery_status = 'ready'    and triggers WhatsApp message to customer:    "Your order is ready and out for delivery! 🚗"SUPABASE QUERY:SELECT orders.*, customers.name, customers.addressFROM ordersJOIN customers ON orders.customer_phone = customers.phoneJOIN bakers ON orders.baker_id = bakers.idWHERE bakers.share_token = TOKEN  AND orders.delivery_date = TODAY  AND orders.payment_status = 'paid'ORDER BY orders.created_at ASCSTYLE:- Warm cream and brown palette (#FAF6F0, #2C1A0E, #C9A96E)- Large tap targets (min 48px height on buttons)- Card-based layout with clear status colours:  placed=grey, baking=orange, ready=green, delivered=blue- No external dependencies — inline CSS + vanilla JS onlyMARK READY FLOW:When baker taps "Mark Ready" on an order:1. 🌅  Your sourdough dough is resting and developing flavour.  Order: {order_number}"JOB 2: "Baking" message → 8:00 AM on delivery dayQuery: orders WHERE delivery_date = TODAY AND delivery_status = 'resting'Action: For each order:  UPDATE delivery_status = 'baking'  Send WhatsApp: "Into the oven it goes! 🔥  Your bread is baking right now.  Order: {order_number}"JOB 3: "Out for delivery" → 11:00 AM on delivery day(Only if baker has NOT already triggered this via dashboard)Query: orders WHERE delivery_date = TODAY AND delivery_status = 'baking'Action: For each order:  UPDATE delivery_status = 'out_for_delivery'  Send WhatsApp: "Your order is on its way! 🚗  Order: {order_number}  Contact your baker if needed."JOB 4: "Delivered" check → 4:00 PM on delivery dayQuery: orders WHERE delivery_date = TODAY  AND delivery_status = 'out_for_delivery'Action: For each order:  UPDATE delivery_status = 'delivered'  Send WhatsApp: "Delivered! 🎉 Enjoy your bread, {name}!  We would love your feedback.  Reply FEEDBACK to share your thoughts.  See you next time. 🌾"Register all jobs in index.js on server start.Log each job run with timestamp and order count to console.Prompt 6 — Final Wiring & Railway Deployment⚠  Run this last to tie everything together and deploy.Wire up the full application and prepare for Railway deployment.FILE: index.js================================- Load dotenv- Import all routes: whatsapp, payments, baker- Mount routes:  app.use('/webhooks', whatsappRouter)  app.use('/webhooks', paymentsRouter)  app.use('/baker', bakerRouter)  app.use('/public', express.static('public'))- Start all cron jobs from deliveryUpdates.js- Health check: GET / → { status: "WWY system running", time: new Date() }- Start server on PORT from envFILE: railway.json================================{  "build": { "builder": "NIXPACKS" },  "deploy": {    "startCommand": "node index.js",    "healthcheckPath": "/",    "restartPolicyType": "ON_FAILURE"  }}FILE: .gitignore================================node_modules/.env/tmp/DEPLOYMENT CHECKLIST:================================1.
